# CarWithin 九号官方投屏观察插件 0.2

目标环境：用户的九号出行 **6.10.13**，iOS **18.7.1**；iPadOS **16.6** 可编译运行，但第一轮优先在实际连接车辆的 iPhone 采集。0.1 已由用户在 iPadOS 16.6、九号出行 6.10.13（3858）上确认浮动面板和录制/停止 Hook 加载；官方投屏后普通转换计数仍为 0。0.2 扩展观察路径，仍需实车复测。

## 这一版能做什么

- 注入后在九号出行自己的窗口添加「投屏诊断」小按钮。
- 按类名和 Objective-C 方法类型检查录制、停止、图像转换观察点。找不到或签名不匹配就跳过，面板标为未匹配。
- 转发原方法，单独统计录制/停止调用、普通与 MJPEG 图像转换调用、非空转换输出、编码回调；不替换画面。
- 面板每 0.5 秒刷新可见计数，关闭后停止刷新。「已挂钩」与「实际调用」分开呈现。
- 报告包含 classMissing / methodMissing / signatureMismatch / hooked 状态和最多 32 条相关类的方法名、类型签名；不自动执行新发现的方法。
- 记录投屏相关 UIKit 控件的 target 类名与 action 选择器，不读取标签、输入内容、参数或车辆报文。React Native/Swift 手势入口可能不经过 UIControl，因此没观察到不等于没点击。
- 用户手动标记开启、仪表出画、关闭的时刻，导出最多 80 条事件的 JSON。只保存在进程内，App 退出后清空。
- CarWithin Build 26 起的「车辆与连接 → 官方投屏助手（验证）」可打开准备过的助手版并导入报告。

**这版不自动激活仪表、不调用猜测的私有方法、不获取车辆令牌、不停止官方视频、不占用九号 UDP 端口。** 视频转换有计数也不能证明仪表已经显示。自动激活与视频交接需要拿到 6.10.13 的调用证据再实现。

## 编译

在带 iOS SDK 的 Mac：

```sh
bash Companion/NinebotProjectionProbe/build.sh build/ninebot-probe
```

产物为 arm64、iOS 16+ 的 `CarWithinNinebotProbe.dylib`。仓库 iOS Actions 同时编译此插件和 CarWithin，产物 ZIP 中包含插件、准备脚本与本说明，不含九号出行 IPA 或签名材料。

## 注入与安装

如果已经在兼容系统上使用 TrollFools，可以直接向已安装的九号出行注入这个独立 dylib；用户的日志和面板截图已证明该路径可以加载插件。此方式不运行下面的 Python 准备脚本，不需要为诊断强行更换注入目标为加密主程序。

若采用重新打包方式，需要你自己准备、可分析和重签的九号出行 6.10.13 IPA。App Store 加密主程序会被准备脚本拒绝；本项目不解密 IPA。没有该 IPA 时，仅能交付独立插件，不能验证版本入口或生成可安装的九号助手版。

使用准备工具：

```sh
python3 Tools/prepare_ninebot_probe.py \
  --ipa /path/to/Ninebot-6.10.13.ipa \
  --probe /path/to/CarWithinNinebotProbe.dylib \
  --output /path/to/Ninebot-6.10.13-probe-unsigned.ipa
```

工具为主程序添加 dylib 加载命令，将插件放入 Frameworks，并注册专用 `cw-ninebot-probe` 打开入口。保留原 Bundle ID、原 URL Scheme 和业务资源，移除失效的 CodeResources；不签名、不安装、不覆盖源 IPA。仅支持有足够空白 Mach-O 头部空间的 thin arm64，遇到不支持的结构直接拒绝。

准备后的 IPA 必须用自己的有效环境安装：普通自签需对插件、嵌套代码与主程序一起正确重签，权限必须与自己的描述文件相容，不能照搬官方专属权限。TrollStore 安装是否可用取决于实际设备系统与工具环境；仅有 IPA 安装能力不代表所有签名或系统版本均可用。官方登录、车辆连接、反篡改和后台行为均需先验证。

也可使用你已有的注入工具把 dylib 放入自己的 IPA 后重签。若未注册助手 URL Scheme，请手动打开修改版。不要修改手机上唯一可用的官方安装实例或删除其数据来测试；可以先用适配自己签名的独立 Bundle ID 安装测试副本，但改 ID 可能影响登录或权限。

## 采集步骤

1. 停止 CarWithin 的 CarPlay，暂时关闭 BMS，避免 UDP 端口和额外蓝牙链路干扰。第一轮仅验证官方链路。
2. 打开修改版九号，确认能正常登录、连接自己的车辆。看见「投屏诊断」按钮才说明插件 UI 已运行。
3. 打开面板，点「开始新的采集」。检查录制/停止是否挂钩，未匹配也可以继续导出报告。
4. 面板点「标记：准备开启官方投屏」，然后手动操作原有投屏入口。
5. 仪表确实出画后，在面板点「标记：仪表已出画（人工确认）」。保持几秒。
6. 点「标记：准备关闭官方投屏」，关闭官方投屏，导出 JSON 并保存到文件。
7. 回到 CarWithin 的助手页导入；报告会显示观察结果，也可预览分享。导入不会执行报告中提到的选择器。Build 27 可完整保留 0.2 的新增诊断字段，Build 26 仅保留旧字段。
8. 五寸和七寸分别采集，说明车型与仪表固件（未知可标未知）。报告本身不获取车辆序列号或固件。

## 下一步的判定

- 能观察录制和图像转换：继续定位更上游的“官方点击 → 车辆就绪 → 模式切换”入口，不能把录制函数当作激活函数调用。
- 观察点未匹配：分析当前 6.10.13 二进制；旧版地址或 Swift 类型名不直接照用。
- 取得稳定入口后，才加入显式激活请求、超时/重复请求处理与完成反馈。
- 最后验证保持官方认证/必要心跳、让 CarWithin 接管视频；无法交接时再评估官方发送链路替换画面的方案。

## 0.1 反馈与 0.2 排查

用户日志显示插件签名、复制到 Frameworks、注入 hermes 并重新签名均成功，最后失败于复制持久插件副本到 `/var/mobile/Library/TrollFools/PersistentPlugins/cn.ninebot.segway/`，报 No such file or directory。截图里插件已运行，所以不能把最后的持久化错误当作 dylib 未加载。TrollFools 的持久化目录问题应在该工具中单独修复；本插件不访问或创建它的全局目录。

替换时先结束九号进程，在 TrollFools 中移除旧的本插件记录，再注入新的同名 `CarWithinNinebotProbe.dylib`，避免同时加载两份。若持久副本仍报错，可检查上述目录是否存在且 mobile 可写，再通过 TrollFools 重试；该操作解决的是后续保存/恢复，不会让图像转换自动命中。

0.2 的判读：普通转换为 0 但 MJPEG/编码回调增长，说明旧版只观察单一路径，不能推断视频没发；调用增长但非空输出为 0，需要看空输出计数；所有路径为 0 时导出 JSON，核对录制入口调用和方法签名，不放宽 ABI 检查或盲调私有函数。
