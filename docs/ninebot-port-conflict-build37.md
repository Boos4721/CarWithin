# 九号本地投屏端口占用 / Build 37

用户日志中 192.168.1.7:5012 返回 EADDRINUSE（Darwin errno 48），发生于 CarPlay RTSP/iAP2 启动之前。用户确认九号出行仍在投屏或后台运行，与官方会话持续占用投屏端口一致；应用无法从此 errno 独立确认占用进程。

## 修改

- 本地 5012/5013 作为一组准备，第二个端口或首个控制发送失败时回滚全部已创建资源，不留下部分绑定。
- 停止和网络恢复时先显式关闭 socket 描述符，再释放 KCP、解码器和编码器，避免对象引用延后端口释放。
- 启动遇到端口占用后每半秒重试，最多等待十秒。端口释放后继续准备通道，只有两个端口和首个控制发送成功后才启动 CarPlay 接收。失败只回调一次；停止/取消会撤销后续重试，旧 generation 不启动新接收器。
- 十秒后仍被占用时明确提示结束九号出行导航投屏，必要时从 App 切换器关闭官方 App 和其他 CarWithin 实例。仅切入后台可能不会释放。
- Wi-Fi 恢复期间遇到端口冲突也使用既有八秒恢复期限，资源失败回滚。
- 保持协议要求的端口，不通过 SO_REUSEPORT 共享接收端口；共享会导致控制回应或七寸 KCP 回包落入其他进程，不能当作可靠接管。

## 验证

新增 macOS 原生真实 UDP 检查：独占视频端口冲突、控制端口冲突时回滚视频端口、显式 close 在引用仍存在时释放描述符、重复关闭、100 次立即启停、初始化中途失败释放。没有运行 iOS 模拟器。其余核心/BMS/车辆配置/兼容性和身份打包检查继续执行，并编译 generic iphoneos arm64 Release。

## 实物限制

这次修复端口冲突的等待、回滚、资源释放和提示，不能强制释放其他 App 的端口，也不能证明独立激活仪表已经成功。如果结束官方投屏后仪表立即退出投屏，仍需要实际验证九号 BLE 配对激活或继续分析官方激活/交接协议。五寸/七寸真实车辆回包和投屏接管仍需实物确认。
