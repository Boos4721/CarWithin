# Build 28 / 九号观察插件 0.3

## 触发证据

用户的 0.2 JSON 来自九号出行 6.10.13（3858）、iPadOS 16.6。录制、停止、普通类转换、MJPEG 类转换、图像编码回调均匹配；实例转换方法不存在。本轮 counters 为空，frameCount 为 0，事件只有清零、两次准备开启标记、前台和人工出画标记。用户确认仪表已显示官方导航/巡航，CarWithin 当时已停止。

因此确认插件已加载、报告功能有效，不能把“没观察到调用”解读为“仪表未投屏”。旧报告不能确定是否采集前已启动、实际走另一编码路径、缓存 IMP/子类/Swift 调用绕过观察点，或者其他 Hook 后续替换了实现。

## 改动

- 依照实测方法清单补充 H.264 与 MJPEG 数据编码回调，仅接受已核对的 void/双对象参数签名，转发原参数和返回流程，不读取数据载荷。
- counters 明确零值；processCounters 保留同进程内清零前的计数，两者同时加锁更新。
- hookChecks 比较当前方法实现，发现不同只报告 replaced，不覆盖。active 不保证每条业务路径经过该方法；replaced 不证明新 Hook 不转发旧 Hook。
- 仅导出时收集最多 16 个相关运行时类，最多 64 条类名/相关方法签名，不实例化、不执行；未暴露给 ObjC 的 Swift 入口仍无法由此发现。
- Build 28 兼容 0.1/0.2 并验证、保留 0.3 的新字段。Build 27 白名单会拒绝含新回调键的报告，测试可直接分享 JSON 而不升级主 App。
- 新采集操作不重装已有 Hook，累计计数保留到 App 进程退出。旧事件和本轮计数仍可清零。

## 验证

新增空计数加人工出画标记回归、本轮与进程累计的区分、编码回调与替换状态保留、可选字段白名单和数量/长度边界。Mac 原生 ObjC smoke 检查双对象回调的原参数/次数转发，以及当前实现被替换的识别。继续运行 IPA 准备工具测试、完整核心测试、iOS Release 和插件 arm64 严格编译；不运行模拟器。

## 实车仍需验证

在官方 App 关闭投屏、确认退出后结束并重开九号，替换插件为 0.3。开始新采集、标记开启、手动开启官方导航/巡航、确认实际出画并等待 5 秒、标记关闭、官方关闭，导出。依据新回调、进程累计、实现检查和上游类清单决定下一步。尚未实现独立激活、视频交接或九号滚轮事件映射。
