# 极核 BMS 仪表卡片 / Build 44

此前 NativeReceiver 只向 NinebotOutput 转发 BMS 卡片；极核 5 寸和独立的 6.2 寸输出都没有收到图像，手机预览正常也不会出现在仪表视频中。

## 输出接入

- BMS 图像与配置同时传给九号、极核 5 寸和极核 6.2 寸输出，启动前保存并在输出队列恢复，运行中更新也在同一队列处理。
- InstrumentVideoCanvas 从 Build 43 的 NinebotVideoCanvas 更名，九号 4.3 寸 JPEG、5/7 寸 H.264 和极核共用同一合成实现。按目标像素尺寸缩放、留黑并合成四角卡片，遵循已保存的字号、位置及背景。
- 极核 5 寸覆盖 SE+ 和 AE2 Pro，输出尺寸仍由仪表协议协商。开启卡片时，如果正在直传则请求源关键帧并切到兼容转码；完成已经取出的直传帧后进入转码，首个转码帧强制 IDR。关闭卡片清除合成图层，本次继续转码，下次启动按原设置决定是否直传。不改写用户的视频模式设置。
- 极核 6.2 寸只增加缓存/转发图像和可选的编码前合成入口；无卡片时继续执行原来的缩放与直通逻辑。原始快照、传输、协商、编码器参数、1024×480 和 25 FPS 均保留。
- 原版 6.2 检查保留原有哈希，只对四处明确的 BMS 适配代码作精确逆变换，再校验完整原输出代码；不放宽协议或协商检查。
- 卡片预览按所选极核画布比例显示，设置说明明确支持范围及转码行为。

## 验证与限制

原生 macOS 验证九号 4.3 寸真实 JPEG 合成、缓存失效、静态画面更新和关闭清除；验证极核 800×480、1600×770、1024×480 及上报竖屏尺寸的四角、三种字号合成。使用应用实际的 H264Encoder 和 TailingH264Decoder 对三种极核画布执行编码/解码，逐像素检查卡片更新和关闭清除，并保留九号 5/7 寸回归。

同时执行现有核心协议、BMS、UDP、车辆配置迁移、极核/台铃/春风集成及身份打包检查，构建 generic iphoneos arm64 Release，不运行模拟器。真实仪表兼容性、运行中直传切换、可读性及锁屏表现仍需实车验证；转码会增加手机负载。
