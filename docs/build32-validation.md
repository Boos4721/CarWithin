# Build 32 / 九号 BLE 配对与导航激活试用

从 xmz28/CarWithin PR #45 的 e70905b2d30fcf848e97788b477ce7d7c4edcecd 提取车辆 BLE 模块与协议测试，适配 codex/ninebot-ant-bms。未将 PR 的整个上游分支合入；原有极核 5 寸统一入口、BMS 统计与卡片、Wi-Fi 和 Build 31 MFi 修复继续保留。

## 操作

1. 通电后，选择九号 4.3、5 或 7 寸输出。在首页「车辆配对 / 自动开启导航」或设置 → 车辆与连接 → 九号车辆配对扫描自己的车辆。
2. 选择扫描结果，点击「建立本机配对」，按车上的 P 键确认。配对成功后还需要在已配对车辆列表明确选择该车。
3. 保存仪表 Wi-Fi 名称和密码，更新车辆配置以绑定 BLE 车辆。Wi-Fi 密码仍需要首次从系统设置复制，不能通过此配对读取。
4. 完全退出九号出行后，点击启动本机 CarPlay。应用先发起车辆认证与导航激活，再加入 Wi-Fi 并启动接收；已连接正确 Wi-Fi 时直接复用。
5. 查看车辆状态「仪表已确认导航开启」与视频输出状态。前者只是 BLE 应答，不能证明仪表已显示画面。
6. 测试停止、再次启动、仪表主动退出、锁屏和 ANT BMS 同时读取。实测失败时保留日志，停止本次连接，在配对页选择「不自动连接」，使用原来的官方 App 激活流程。

## 集成行为

- 只有用户点击配对才写入新密钥；每个设备的已确认/待确认密钥留在 Keychain，自动重连不发起配对。车辆预设只保存可选的 BLE UUID 引用，兼容旧预设。
- 新选车会更新当前车辆配置。切换车辆预设时，缺失或已删除的配对引用会清空上一个车辆选择；正在配对/断开期间禁止切换预设。
- 未连接目标 Wi-Fi 时，最多等待 BLE 激活 30 秒再申请加入，暂时性的系统 pending/internal 错误最多重试 5 次。保留原有 60 秒总超时、取消按钮和显式拒绝处理。
- 加入 Wi-Fi 失败、取消或手动停止时，结束车辆会话；Wi-Fi 地址变化及画面设置引起的自动重启保留车辆导航连接。仪表主动退出后本次不自动重新开启。
- BLE 状态写入现有日志，不记录密钥。启动失败仍可手动使用九号出行。保留独立 ANT BMS 连接；原车滚轮输入尚未实现。

## 验证范围

运行完整核心测试、上游配对/导航命令约束与向量测试，补充认证重放/篡改、认证候选轮换、广播证据、帧分片边界及车辆绑定恢复检查。临时 UserDefaults 迁移检查增加旧预设无绑定和新 UUID 往返。执行原有极核/台铃兼容检查、MFi 本地打包回归、generic iOS arm64 Release 构建，不使用 iOS 模拟器。

本机没有 Apple SDK，协议执行和编译在 macOS CI 完成；真实 MFi 身份仅在本机打包。BLE 实现是实验性接入，仍需要真实车辆验证配对确认、与官方 App 的连接切换、4.3/5/7 寸自动出画、停止及后台行为。编译或单元测试通过不等于这些场景已通过。
