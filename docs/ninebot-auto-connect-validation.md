# 九号自动连接真机验收

当前变更尚未经过 Xcode 编译和真机验证。需使用具有 Hotspot Configuration / Access WiFi Information 权限的签名，在 iOS 16+ 真机执行以下检查。

1. 输入正确的 WPA/WPA2 Wi-Fi 名称与密码，保存并加入；确认首次系统提示，成功后应显示已连接。开放网络另测一次。
2. 先连接家庭 Wi-Fi，再启动九号输出：必须切换到仪表 SSID，等待稳定 IP 后才启动 CarPlay，不能使用家庭网络误启动。
3. 错误密码、热点关闭、拒绝系统提示、缺少签名权限：应显示失败或超时，恢复可操作状态，不能启动 CarPlay或反复弹窗。
4. 等待系统提示或 IP 分配期间取消连接，随后允许旧系统提示：App 不应再启动 CarPlay。注意系统可能仍完成 Wi-Fi 加入，App 取消不撤销系统网络操作。
5. 连续点击连接不应产生重复请求；取消后重新连接，旧请求不能更改新请求状态。
6. 开启自动连接后结束并重新打开 App：预设、有效身份齐全时自动加入并启动；关闭开关则不自动启动。手动停止或失败后，切后台再返回不应再次自动尝试。
7. 在 Wi-Fi 设置页编辑未保存信息时、使用其他输出时、无有效身份时，不应自动启动。
8. 成功加入后切换到九号出行再返回，Wi-Fi 配置不应因 App 进入后台而被删除。7 寸与 4.3 寸按原有说明在九号出行激活投屏。
9. 分别验证 5 寸、7 寸、4.3 寸输出，检查画面与各型号原有握手行为。Wi-Fi 成功不代表仪表已确认视频。
10. 在模拟器和 Mac Catalyst 点击加入应提示需要真机；浏览器、CarLife、极核和台铃原有启动流程不应改变。

自动连接范围：每次进程运行最多自动尝试一次，不提供系统后台唤醒、车辆蓝牙自动配对或仪表 Wi-Fi 密码发现。

## 五寸与七寸端口预启动验收

分别以五寸和七寸冷启动仪表，确保九号出行未运行，再点击启动本机 CarPlay：

- 日志应先出现「九号投屏端口 5012/5013 已就绪，已发送首个控制握手」，再出现「九号投屏通道已准备，继续启动 CarPlay 接收服务」，最后出现 RTSP 监听器就绪。
- 五寸检查控制回应与实际出画；七寸检查 KCP 会话号、视频确认及实际出画。仅有“端口已就绪”不算通过远端激活验收。
- 占用本机 UDP 5012 或 5013 后启动，应报告通道失败，不能继续启动本机 CarPlay；释放端口后可重新启动。
- 在通道准备期间停止，然后立即重启：旧准备回调不能启动新会话的 RTSP 监听器。
- 若无九号出行不能出画，记录车型、仪表固件和各阶段日志，并采集九号出行“开启投屏导航”前后的控制通信以定位缺少的激活步骤。当前实现没有新增未经验证的远端激活报文。

## 复用系统自动连接的 Wi-Fi

- 五寸、七寸分别验证：先由 iOS 自动加入已保存的仪表 Wi-Fi，再在 CarWithin 启动。允许精确定位且签名权限齐全时，应出现“复用当前网络”日志，不再请求加入网络。
- 点击“读取当前 Wi-Fi”，确认填入当前 SSID；已有密码应按该 SSID 从本 App Keychain 读取。系统保存的密码不会被导入。
- 先连其他网络：不能走复用分支，应申请加入所选仪表网络，确认匹配与稳定 IP 后再启动。
- 拒绝定位或禁用精确定位，导致 SSID 无法读取：允许使用已保存配置申请加入；若之后仍无法确认 SSID，应超时提示，不能仅凭 IP 启动。
- 当前网络已匹配但 IP 未就绪：继续等待，不重复申请加入，也不提前启动。等待期间换网络或取消，不能误启动。
- 关闭实验选项时，首次未填加密网络密码仍提示补全；开启实验后按下文验证仅记住 SSID。两种情况下均不得把加密网络自动标为开放网络。

## 五寸、七寸：省略 Wi-Fi 配置的实验

开关默认关闭。先在九号输出设置开启「使用当前 Wi-Fi 启动（实验）」，再分别对五寸、七寸验证以下场景。

| 场景 | 预期 |
| --- | --- |
| 已连接所选 SSID，无本 App 密码 | 可以仅记住名称并启动；0x4301 首次请求不含参数组 1；Wi-Fi 不被重配为开放网络 |
| 已连接所选 SSID，有正确密码 | 首次仍省略参数组 1；如控制连接未建立，首次请求 12 秒后回退一次，后续请求携带原 SSID、真实密码、信道和安全类型 |
| 无密码，实验未建立控制连接 | 12 秒后停止并提示补全密码，不能无限请求或提交虚假凭据 |
| 控制连接在 12 秒内建立 | 不执行密码回退，继续正常协商、发送画面 |
| 12 秒内手动停止、重启 | 原会话的回退与 3/6/9 秒重试均失效，不能更改新会话 |
| 连着家庭 Wi-Fi，无仪表密码 | 提示先连仪表网络或补全密码，不调用加入 API，不启动 CarPlay |
| 连着家庭 Wi-Fi，有仪表密码 | 使用保存凭据加入；SSID 和稳定 IP 确认后走原有凭据启动，不采用实验报文 |
| 无精确定位、SSID 读取失败，无密码 | 提示权限与连接要求，不只凭 IP 启动 |
| 仅保存名称，Keychain 原本已有密码 | 原密码保持不变；预设仍标为加密网络，不能被空值覆盖 |
| 重开 App | 实验开关和所选 SSID 保留；打开 App 自动连接仍尊重原开关 |
| 浏览器、CarLife、极核、台铃、4.3 寸或投送到 iPad | 不提供实验开关；原有报文保留 Wi-Fi 配置 |

`Tools/test.sh` 会包含 `CarPlayWiFiBootstrapTests`，覆盖实验报文省略、凭据回退、安全类型、开放网络和默认模式。静态/协议验证不能替代上述真机测试。日志不得包含密码。

## 身份配置入口（Build 17）

1. 无身份时，主页显示可点的“配置身份 / 从原版 IPA 导入”；设置中始终有“CarPlay 身份”入口。
2. 从九号连接入口启动但无身份时，应导航到身份页，只提示缺少身份，不再错误要求重新选择已处于的本机模式。
3. 导入含完整身份的原版 IPA：本地签名匹配通过后保存 Keychain、启用启动按钮、隐藏主页缺失提示；重启 App 后仍可载入。
4. 选择三个正确文件应有相同行为；取消选择、缺文件、证书不匹配、无效/加密/超限/重复资源归档均不能覆盖已有身份。
5. 导入 HTTPS P12 仍走原有密码弹窗，不应被识别为 MFi 导入；取消任一选择器后再次操作应保持类型正确。
6. 全流程不上传文件，不更改用户选择的原文件，日志不输出私钥或证书正文。最终 iOS 认证失败仍显示原有协议错误，不能仅凭本地匹配宣称认证成功。
