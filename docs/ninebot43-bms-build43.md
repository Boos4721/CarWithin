# 九号 4.3 寸 BMS 仪表叠加修复 / Build 43

根因：NinebotOutput.Session.setBMSOverlay 在 usesJPEG 时直接丢弃 BMS 图像，因此手机预览可显示而九号 4.3 寸 JPEG 视频没有电池卡片。

## 修复

- JPEG 和 H.264 共用 NinebotVideoCanvas，接收同一张实时卡片位图，按已保存的四角位置与大小合成。
- 九号 4.3 寸在 480×272 JPEG 编码前加入卡片，仍保留原 JPEG/RTP 分包、控制握手、10 FPS 限速和软件渲染配置。
- 卡片数据、位置、大小或开关更新会清空 JPEG 缓存，静止 CarPlay 画面也刷新，不残留旧卡片。失联仍由现有实时卡片显示等待状态，不引入示例数据。
- 五寸/七寸 H.264 保留原缩放、留黑与无卡片同尺寸直通路径。
- 设置中的 4.3 寸布局预览使用实际 480:272 比例，更新支持范围说明。

## 验证

新增原生 macOS Core Image 图像验证，实际生成并解码 JPEG 后检查四角叠加、480×272 尺寸及背景，验证无新视频时卡片数据更新、位置变化、关闭清除、JPEG 缓存与尺寸变化，并验证五寸/七寸 H.264 输入画布及无卡片直通。由 CI 执行并保存 ninebot-canvas-tests.log，不使用 iOS 模拟器。

同时运行既有 BMS、核心协议、UDP、车辆迁移、输出集成及身份打包检查，编译 generic iphoneos arm64 Release。仪表最终可读性、JPEG 传输和真实车辆背景刷新仍需实车验证。
