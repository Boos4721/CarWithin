# PR #80：九号配对与导航修复（Build 50）

基于开发分支 Build 49，合入上游 PR #80 的 `e6defb4547dc3b0b111ae5d56e513cf7a729251d`，保留贡献者提交历史。上游 PR 本身是否合并，由上游维护者决定；本次目标是我们的开发分支。

## 合入能力

- 导航开启确认兼容空载荷、单字节 `00` 和 `01`；错误来源、地址、索引及其他载荷不能确认开启。
- 配对先等待车机 `04 → 3E / 5C / index 0 / 空载荷` 就绪通知，再高亮提示短按 P 键，并开始 60 秒倒计时。
- 首页及配对页增加当前所选车辆的一键重新配对；系统缓存丢失时定向扫描，仅连接该车辆的 UUID。
- 就绪前旧会话回复及准备超时，可恢复当前用户明确授权的配对操作；五次重连后停止。
- 诊断与实验增加最近 80 条蓝牙状态日志，可复制与清空；记录命令元信息，不记录配对密钥、认证参数或原始认证载荷。
- 保留开发分支的车辆别名、找车对照、扫描诊断、目标确认、配对进度、BMS、Wi-Fi 恢复和多仪表输出。

## 对 PR 恢复逻辑的调整

- 不自动删除待确认密钥，不在每次恢复时强制生成新密钥。车端可能已经写入而确认包丢失，保留并复用同一份写前保存候选，认证成功后才提升为确认密钥。
- 明确配对授权只在当前车辆、本次操作内有效，取消、超时和结束时清除；普通投屏认证失败不能自行进入 `SET_PWD`。
- 倒计时以首个有效就绪回复为准，重复回复不续期；准备阶段按实际发送请求数及时间双重限界。
- 两秒未收到断开回调时，替换 CBCentralManager 并检查中央管理器身份；外设代理绑定会话 epoch，旧代理回调不能作用于重试中的同一外设。
- 重建管理器仍消耗原有重连预算，不形成无限快速恢复循环。
- PRE_COMM 的 SN 长度优先使用有效广播长度；缺失时只接受 1–64 字节的有界剩余长度。截断及非法长度停止认证。

## 验证范围

新增纯协议测试及原生 macOS 的生产连接状态机检查，使用内存 BLE、Keychain 和加密替身覆盖就绪、密钥保留、取消、定向扫描和过期回调。真实加密由既有核心协议测试验证，真实 CoreBluetooth／Security 接口由 iphoneos arm64 Release 编译验证。

这些自动检查不能代替实际车辆配对与出画验证。PR 作者报告的是 4.3 寸实测结果；本机未连接用户车辆，5 寸／7 寸及具体固件仍待用户实测。MFi 加载方式沿用 Build 49；构建不使用 iOS 模拟器。
