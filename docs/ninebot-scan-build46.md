# 九号车辆蓝牙扫描可见性 / Build 46

用户反馈 PR #45 的车辆功能在其车辆上无法复现，进一步确认是“没有找到我车的蓝牙”，尚未进入配对或认证阶段。PR 最新 head 仍为 c9b2620aa5e99d5f42569a80776af3530acba70a，已有整合。PR 讨论中的认证失败不是本次扫描失败的已确认原因。

## 已确认的代码行为

底层原本已执行 `scanForPeripherals(withServices: nil)`，并不按名称或 RSSI 过滤射频扫描；但页面只显示 `Advertisement.parse` 成功的设备。缺少厂商数据、格式不完整、校验错误、其他厂商的设备都被隐藏。因此“列表为空”不能区分没有收到广播和没有识别广播。

## 调整

- 新增独立的 NinebotScanDiagnostics 库存，记录本轮广播数、最多 100 个设备、广播名/系统缓存名、RSSI、服务 UUID、厂商前两个原始字节与长度，以及具体解析状态。
- 原“附近车辆”继续只列经过九号广播识别的设备；新增可展开的“附近其他蓝牙（未确认）”。无名称、信号弱、通用 UART 或广播校验失败的设备可以在诊断列表中看到。它们不会自动连接，也不能发送配对请求。
- 扫描开始时只读查询系统当前连接的 Nordic UART 设备，单独标注“扫描开始时系统已有连接”。缓存名称与服务提示不证明品牌、归属或握手可用，不增加配对资格，不抢占其他 App 的连接。
- 空态区分“本轮零广播”和“收到广播但未识别九号”。扫描摘要可复制为 JSON，便于用户贴回诊断。包含设备名称和本机标识，不包含完整厂商载荷、配对密钥或认证报文；本机 UUID 不称为 MAC。
- 报告每秒最多发布一次，停止时刷新；新扫描清空旧库存。达到上限优先移除未识别的旧记录，保留已识别设备；记录截断次数。
- 原 DiscoveryEvidence、厂商校验、真实广播名称要求、协议版本限制、可连接标志与新鲜度检查都保留。两轮找车仍只比较有配对资格的设备，不因通用 UART、名称或 RSSI 自动认车。
- 保留 Build 45 陆行和此前全部 BMS／仪表输出修复。

## 验证和边界

新增 10 项核心测试，覆盖未识别设备可见、证据分片后升级、缺少真实广播名称、错误厂商/格式/校验状态、已验证证据保留、100 台上限与淘汰、系统已连接设备、JSON 摘要不含原始载荷、空扫描及不支持版本保持阻断。

CI 运行完整核心、BMS、图像编码和输出集成测试并编译 generic iphoneos arm64 Release，不使用模拟器。此改动解决隐藏信息导致无法排查的问题；未取得用户车辆的实际广播前，不能断言根因是新格式、其他 App 占用或车辆未广播，也不能保证该车辆可完成 PR #45 的配对认证。
